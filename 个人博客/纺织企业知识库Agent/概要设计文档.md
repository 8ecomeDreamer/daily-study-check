# 纺织外贸跨境多智能体运营工作台 — 概要设计文档

版本：v1\.0

文档类型：概要设计（HLD）

技术栈：SpringBoot 3 / Maven 多模块 / Spring AI / RAG 向量库 / 多模态图像识别 / MySQL / Redis / MinIO / Vue 3

## 1\. 项目概述

### 1\.1 项目背景

本项目面向牛仔面料 B2B 外贸业务场景，基于企业现有纺织 ERP 系统，叠加 AI 多智能体能力，搭建轻量化、高适配的外贸智能运营工作台。项目不替代原有企业ERP，仅作为**AI智能业务增强层**，帮助外贸业务员解决日常核心业务难题，依托纺织专属知识库、ERP真实业务数据、外网行业数据，实现标准化、智能化业务处理，告别人工多系统切换、人工核对、人工调研的低效模式。

系统核心支撑五大核心业务：**纺织专属智能问答、ERP联动智能报价、海外面料竞品调研、外贸单证合规校验、面料图片智能识别**，全面覆盖外贸业务员高频工作场景。

### 1\.2 业务痛点

1\. **纺织咨询答疑低效**：业务员面对客户各类纺织工艺、面料参数、外贸常识问题，依赖个人经验解答，新人上手慢，答复不标准、无依据。

2\. **询盘报价繁琐易出错**：客户非标询盘需人工查阅ERP成本、面料参数、库存数据，手动编写中英文报价邮件，格式混乱、核算耗时，易出现报价失误。

3\. **竞品调研成本极高**：海外面料供应商网站分散，人工搜集同款面料价格、工艺、参数耗时久，难以快速输出标准化竞品对比资料，支撑定价决策。

4\. **外贸单证合规风险高**：PI、销售合同、贸易条款等单证无标准化校验手段，人工审核易遗漏合规漏洞，引发外贸纠纷、商检风险。

5\. **面料质检依赖人工经验**：客户寄样、现场面料图片需人工肉眼识别面料品类、排查疵点，效率低、标准不统一、漏检率高。

### 1\.3 项目目标

1\. 搭建**多Agent协同架构**，分工实现五大核心业务能力，通过总控Agent统一调度子Agent，实现业务流程自动化、标准化。

2\. 构建**纺织专属RAG知识库**，沉淀面料工艺、外贸规范、行业标准，实现问答、校验业务可溯源、可审计，杜绝AI幻觉。

3\. 深度对接企业纺织ERP，通过工具调用获取真实成本、面料参数、库存数据，支撑精准智能报价，替代人工查表核算。

4\. 集成外网数据抓取、多模态图像识别能力，实现竞品自动调研、面料智能质检，大幅降低人工成本。

5\. 引入后置反思校验Agent，对报价结果、单证合规结论、面料识别结果做二次校验，保障核心业务数据真实可靠。

## 2\. 系统分层架构图

![design_1.png](images%2Fdesign_1.png)

### 架构说明

系统自上而下分为五层架构，极简轻量化、高内聚低耦合，完全适配本项目五大核心业务：

1\. **前端工作台层**：基于Vue3搭建统一操作入口，支持文本问答、图片上传、询盘报价、单证校验、报告预览导出，承载所有用户交互场景。

2\. **应用服务层**：SpringBoot核心业务层，负责接口鉴权、用户会话管理、MinIO文件存储管理、业务请求分发，是前端与智能Agent层的中转枢纽。

3\. **多Agent智能核心层**：系统核心能力载体，采用**Plan\-And\-Execute\+ReAct\+Reflection**三大AI范式，各Agent单一职责、协同工作，覆盖全部核心业务，后置校验杜绝幻觉。

4\. **基础能力层**：通用AI能力底座，提供纺织专属RAG检索、工具调用、大模型路由、全链路日志追踪，为所有Agent提供统一能力支撑。

5\. **外部系统层**：对接企业内网ERP获取真实业务数据、抓取外网竞品行业数据、调用视觉模型实现图像识别，为AI业务提供真实数据源。

## 3\. 系统核心功能模块结构图

![design_2.png](images%2Fdesign_2.png)

### 模块功能说明

严格基于既定五大核心业务\+基础系统能力设计，无冗余无效模块：

1\. **综合问答模块**：依托纺织专属RAG知识库，仅响应纺织工艺、面料参数、外贸行业相关问题，自动过滤无关咨询，输出标准化、可溯源的专业答复，统一业务员答疑口径。

2\. **智能报价模块**：核心盈利业务模块，自动解析客户中英文询盘，调用ERP获取面料成本、规格、库存数据，智能核算报价，一键生成标准中英文报价邮件，支持MD、PDF格式导出，无需人工编辑。

3\. **竞品调研模块**：输入目标牛仔面料参数后，自动抓取海外主流供应商同款面料的价格、工艺、克重、门幅等数据，完成横向比对，生成专业竞品分析报告，为企业定价、接单提供数据支撑。

4\.**合规校验模块**：支持用户上传PI、销售合同、外贸条款等文件，结合外贸合规知识库，智能校验条款合规性、参数合理性，精准标注风险点、违规项，规避外贸交易风险。

5\. **面料识别模块**：多模态AI能力落地，用户上传面料实拍图片，自动识别面料品类、检测破洞、色差、跳纱等疵点，标注疵点位置与置信度，自动生成质检简报。

6\. **系统管理模块**：支撑系统稳定运行，提供知识库文档上传、更新、下线能力，搭配用户权限管控、Agent调用日志、会话历史审计，满足企业内部运维与合规审计需求。

## 4\. 多Agent核心业务流程设计

渲染地址：[https://mermaid\.live/](https://mermaid.live/)

```Plain Text
flowchart TD
    START([用户发起业务请求]) --> INPUT{请求类型判断}

    %% 五大业务入口分发
    INPUT -->|纺织知识提问| Q1["综合问答业务"]
    INPUT -->|询盘报价需求| Q2["智能报价业务"]
    INPUT -->|竞品调研需求| Q3["竞品调研业务"]
    INPUT -->|上传单证校验| Q4["合规校验业务"]
    INPUT -->|上传面料图片| Q5["面料识别业务"]

    %% 统一进入总控Agent
    Q1 --> PLAN["Plan总控调度Agent意图识别+任务拆解"]
    Q2 --> PLAN
    Q3 --> PLAN
    Q4 --> PLAN
    Q5 --> PLAN

    %% 各子Agent执行对应业务
    PLAN --> A1["RAG问答Agent知识库检索答疑"]
    PLAN --> A2["智能报价Agent调用ERP+生成邮件"]
    PLAN --> A3["竞品调研Agent抓取外网竞品数据"]
    PLAN --> A4["合规校验Agent单证合规智能审核"]
    PLAN --> A5["面料识别Agent多模态图像质检"]

    %% 所有业务结果统一进入反思校验
    A1 --> RECHECK
    A2 --> RECHECK
    A3 --> RECHECK
    A4 --> RECHECK
    A5 --> RECHECK

    RECHECK["Reflection反思校验Agent数据校验+纠错去幻觉"]
    RECHECK -->|校验失败| RETRY["重试执行对应业务Agent"]
    RETRY --> RECHECK
    RECHECK -->|校验通过| OUT["生成标准化业务结果问答/报价/报告/质检简报"]

    OUT --> EXPORT["支持MD/PDF导出+会话持久化"]
    EXPORT --> END([返回前端展示])

```

### 流程核心说明

本流程完全贴合**三大AI范式**，解决你之前的架构疑惑，无过度封装、每一步均有实际业务价值：

1\. **Plan\-And\-Execute（总控调度）**：接收用户所有业务请求，完成意图识别，将复杂业务需求拆解为独立子任务，统一调度对应子Agent执行，解决复杂多步骤业务混乱、漏步骤问题，是系统的业务总指挥。

2\. **ReAct（子Agent执行）**：五大业务子Agent均基于ReAct范式开发，通过「思考\-调用工具\-获取结果」循环，实现RAG检索、ERP接口调用、外网数据抓取、图像模型调用，强制依赖真实数据，从根源减少AI幻觉。

3\. **Reflection（后置校验）**：所有业务执行完毕后，统一进入反思校验Agent，核对问答准确性、报价数据合理性、调研数据真实性、单证合规性、面料识别精准度，异常则自动重试，保障所有输出结果可落地、无错误。

4\. 简单业务（普通纺织问答）快速执行，复杂业务（报价、调研、校验）多Agent协同，兼顾响应速度与业务准确性。

## 5\. 数据存储简要说明

|存储介质|核心用途|存储内容|
|---|---|---|
|**MySQL**|结构化业务数据持久化|用户权限数据、会话记录、Agent调用日志、知识库元数据、业务操作记录|
|**Redis**|缓存与会话状态管理|短期会话记忆、Agent任务中间状态、高频查询数据缓存、接口限流|
|**向量库（PgVector）**|纺织RAG知识库检索|牛仔面料工艺文档、外贸合规条款、行业标准、业务问答知识库切片向量|
|**MinIO（私有化OSS）**|非结构化文件存储|用户上传面料图片、外贸单证原件、生成的PDF/MD报价报告、质检简报、知识库原文档|

**存储设计说明**：采用「结构化数据\+向量数据\+文件数据」分层存储，业务核心数据落MySQL，智能检索依赖向量库，静态文件私有化存储MinIO，数据不出企业内网，安全可控、便于运维。

## 6\. 非功能需求

### 6\.1 性能需求

1\. 简单纺织问答响应时长 ≤ 2秒，复杂报价、调研、校验全流程响应 ≤ 8秒；

2\. 面料图片识别推理时长 ≤ 3秒，大文件单证解析无卡顿；

3\. 支持50人并发在线使用，长链路业务异步处理，不阻塞前端操作；

4\. 高频知识库问答、ERP参数查询支持缓存加速，提升响应效率。

### 6\.2 安全需求

1\. 权限隔离：基于角色管控功能权限与数据权限，业务员仅可查看自身业务数据；

2\. 数据安全：MinIO私有化部署，业务文件、面料资料、单证数据留存企业内网，不对外上云；

3\. 输入校验：拦截恶意Prompt注入、非法文件上传，保障系统稳定；

4\. 操作审计：完整记录所有Agent调用、文件上传、业务操作日志，可追溯、可复盘。

### 6\.3 可扩展性

1\. Agent可插拔：新增业务能力仅需新增子Agent，注册即可使用，无需改动核心调度架构；

2\. 工具可扩展：支持新增ERP接口、外网数据源、识别模型，适配后续业务迭代；

3\. 知识库可热更新：支持文档增量上传、下线、更新，无需重启服务；

4\. 存储可切换：封装统一文件存储接口，当前使用MinIO私有化部署，可无缝切换阿里云OSS公有云存储。

### 6\.4 AI幻觉治理（核心亮点）

1\. **工具优先原则**：报价、参数查询、调研数据强制调用ERP/外网真实接口，禁止大模型凭空编造；

2\. **RAG溯源机制**：所有纺织问答、合规校验结论必须关联知识库原文，无有效溯源不输出结果；

3\.**双层校验机制**：ReAct执行获取数据 \+ Reflection后置纠错，双重保障业务数据准确；

4\. **置信度管控**：面料识别结果低于置信度阈值时，标记待人工复核，避免错误结果落地。

## 7\. 核心架构范式落地总结（可直接用于答辩/简历）

本项目摒弃传统单大模型Prompt开发模式，采用**多智能体分层协同架构**，精准落地三大AI主流范式，无无效封装、所有设计均服务于纺织外贸核心业务：

1\. **Plan\-And\-Execute 规划执行范式**：用于顶层总控Agent，负责复杂业务意图识别、任务拆解与子Agent调度，解决多步骤业务流程混乱、功能遗漏问题；

2\. **ReAct 推理行动范式**：所有业务子Agent基于该范式开发，通过工具调用获取ERP、外网、知识库、图像模型真实数据，适配不确定次数的工具调用场景，适配业务不确定性；

3\. **Reflection 反思校验范式**：独立后置质检Agent，对所有业务输出结果做事实校验、合规校验、数据一致性校验，从架构层面解决AI幻觉问题，保障B端外贸业务数据零失误。

同时基于**MinIO私有化对象存储**管理所有业务文件，对接企业内网ERP，实现数据安全可控、业务高效自动化，完全适配纺织外贸企业私有化部署、低风险、高精准的业务需求。
